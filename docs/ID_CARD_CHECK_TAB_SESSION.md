# Проверка карточек ИД: сессия вкладки

## Требования

Список EdocID и позиция просмотра нужны только в специально открытой вкладке.
Навигация сохраняется при переходах между карточками, разделами карточки,
перезагрузке страницы и странице ошибки. Закрытие вкладки завершает просмотр.
Новая вкладка получает новый список; параллельные просмотры независимы.
Ручное открытие карточки не подхватывает чужой список. Вход в Supabase не нужен.

## План

1. Перед открытием первой карточки передать список в временную сессию новой вкладки.
2. Хранить сессию по tabId в chrome.storage.session; sessionStorage страницы
   использовать только для раннего отображения навигации в той же вкладке.
3. При закрытии вкладки удалить сессию. Не восстанавливать список из старого
   chrome.storage.local или Supabase.
4. Исключить dup_id_card_check_state_v1 из синхронизации, импорта и старой очереди.
5. На сервере исключить ключ из allowlist, удалить только старое состояние
   просмотра и игнорировать такие операции старых клиентов без новых записей журнала.
6. Проверить навигацию, изоляцию вкладок, закрытие и Firefox-сборку; закоммитить
   только изменения этой задачи.

## Scope gate

- StageTimer: нет.
- Firefox-совместимость: да, временное хранение и преобразование background.
- Content/background scripts и деплои: да, существующие файлы без новых ресурсов.
- Новые элементы UI, F2 и скрытие при скриншоте: нет.
- Новые постоянные локальные ключи: нет; сессия вкладки не синхронизируется.
- Supabase: да, исключение временного ключа и совместимость старых клиентов.
- Apps Script / Google Sheets: нет.

## Проверка

- Два разных списка не влияют друг на друга.
- Переход и перезагрузка сохраняют список и правильную позицию.
- Новая/закрытая вкладка не получает прошлую сессию.
- Изменение позиции не вызывает DUP_SYNC_SET и облачных операций.
- Очистка старой очереди сохраняет остальные операции смешанного пакета.
- Серверный no-op не увеличивает revision и журнал; прочие ключи остаются разрешены.

## Использование

В F2 загрузить список EdocID: откроется отдельная вкладка с навигацией.
Закрыть вкладку для завершения просмотра. Для следующего просмотра загрузить
новый список. После обновления расширения старые вкладки следует перезагрузить;
список завершённого старого просмотра автоматически из облака не восстанавливается.

## Результат проверки

Проверены обработчики с моделированием browser API: передача списка до загрузки
страницы, два независимых просмотра, позиция после перехода и повторной загрузки,
отсутствие сессии у новой вкладки/iframe, удаление после закрытия, сохранение
остальных операций смешанной очереди. Проверено преобразование background для
Firefox: временное хранилище карточек не заменяется на storage.local.

Миграция применена через Supabase MCP. Ключ запрещён, старые значения удалены
из текущего и legacy-состояния. Серверный тест старого ключа и пустого пакета
подтвердил отсутствие новых revision и записей журнала. Тест выполнен с rollback.
Проверка в живой вкладке браузера в этой задаче не выполнялась.
