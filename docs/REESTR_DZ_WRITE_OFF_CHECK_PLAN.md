# План: проверка списания по реестрам ДЗ

1. Превратить кнопку проверки исходящих в кнопку-меню «Проверка» с двумя согласованными действиями.
2. Добавить отдельную модель дневной сессии новой проверки по `depid`, восстановление и исключение
   уже обработанных строк текущего дня.
3. Повторно использовать период по «Дате запуска поручения на списание» и сбор всех страниц грида,
   оставляя строки с исходящим и незаполненной датой либо номером приказа.
4. Отделять исключённых взыскателей до видимого цикла: сразу фиксировать пропуск, а при отсутствии
   обычных кандидатов немедленно формировать отчёт проверки исходящих.
5. Расширить фоновую работу с WSS: извлечь исходящий, количество, сумму, ответственного, решение,
   входящие и другие документы.
6. Добавить переносимый между страницами компактный оверлей ручной сверки, навигацию по документам,
   маску даты, свободный номер приказа и клавиатурный поток `Tab`/`Enter`.
7. Подсвечивать исходящий и нормализованную целую часть суммы на HTML-страницах WSS.
8. После подтверждения пользователя возвращаться к строке, штатно сохранять решение в комментарии,
   затем штатно сохранять дату и номер приказа с проверкой значений в гриде.
9. Отсутствие решения вместе с отсутствием документов считать успешным результатом «Не найдено»;
   несовпадение наличия решения и документов останавливать для ручной проверки. Для отказа с
   документом сохранять только комментарий.
10. Перед повторной обработкой строки с существующим комментарием показывать подтверждение с
    данными реестра; по умолчанию предлагать пропуск с управлением `Enter` и стрелками.
    Анимировать смену реестров, показывать позицию, разрешить сохранить сокращённый фрагмент
    комментария как общее правило автопропуска и управлять правилами через ✏️/❌.
11. После основной логики обеих проверок независимо переносить дату и пояснение решения
    «Аннулировать» в комментарий реестра без изменения результата строки и без дублей.
12. При завершении проверки списания формировать отдельный Excel со всеми результатами и зелёной
    заливкой строк, где расширение фактически изменило комментарий либо реквизиты приказа; добавить
    повторное скачивание из завершённого оверлея.
13. Добавить новые элементы в скрытие при скриншоте и существующую настройку F2.
14. Выполнить точечные синтаксические, deploy- и UTF-8-проверки, затем создать отдельный коммит.
15. Добавить общий пул из 1–5 фоновых вкладок WSS: параллельно подготавливать группу поручений,
    дожидаться всей группы и последовательно выполнять ручную сверку и сохранение по порядку грида.
16. Синхронизировать общий словарь автопропуска комментариев через разрешённый KV-ключ Supabase.
17. Запоминать выбранный размер пула локально и включить настройку в Supabase-синхронизацию.
18. В ручном оверлее добавить режим «Пропустить»: редактировать предзаполненное решение, вернуть
    комментарий в Пирамиду и сохранить только его без формы приказа.
19. Для решения другого сотрудника добавить промежуточную ручную сверку поручения: предупреждение
    и кнопка «Проверить» в основном оверлее, подсветка ответственного и допустимых решений,
    подтверждение замещающего решения либо пропуск с необязательным комментарием.
20. Закрывать фоновые WSS-вкладки сразу после подготовки группы и очищать оставшиеся неактивные
    вкладки предыдущей проверки после перезагрузки расширения.
21. Надёжно собирать вложения WSS по имени файла и динамической разметке; показать в ручном оверлее
    реквизиты приказа и разбивку суммы из поручения.
22. Ограничить вложения ручной проверки PDF-файлами и открывать proxy-файлы WSS во внутреннем
    просмотрщике новой вкладки с переносом оверлея и закрытием прежней вкладки.
23. Включить общую сумму в блок состава суммы списания.
24. После ручной проверки ожидать все строки новой группы на целевой странице грида и один раз
    повторять загрузку страницы при рассинхронизации pager и строк.
25. Внутри группы сохранять жёлтый статус ожидания и последовательно заменять его зелёным либо
    красным результатом строки, восстанавливая цвета после перезагрузки грида.
26. Распознавать архивные вложения ручной проверки, локально извлекать из них только PDF и
    добавлять найденные файлы в существующий список документов с ограничениями безопасности и
    видимым прогрессом скачивания и распаковки.
27. Автоматически разбирать ZIP, показывать компактный прогресс внутри ручного оверлея и временно
    кэшировать результат по номеру входящего/другого документа до завершения всей проверки.
28. Выполнять фоновый разбор архива без закрытия страницы WSS и разворачивать внутренний
    просмотрщик только после выбора конкретного PDF.
29. Хранить разобранные архивы между запусками проверки в течение текущего календарного дня и
    удалять записи прошлых дат при первом запуске проверки на следующий день.
30. Обрабатывать несовпадение исходящего в поручении и гриде отдельным ручным оверлеем: дать
    отредактировать комментарий, штатно сохранить его без приказа и продолжить следующую строку.
31. В ручной проверке отсутствующего решения ответственного разрешить выбрать один из трёх
    допустимых вариантов и подтвердить его, даже если парсер не предложил решение автоматически.
