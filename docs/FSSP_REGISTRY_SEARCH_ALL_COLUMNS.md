# Поиск по всем столбцам реестров ФССП

## Спецификация

Один общий блок фильтров определяет список реестров для всех условий поиска.
Поля и варианты выбора берутся из фильтров текущей страницы: идентификатор,
тип, статус, файл, дата создания, пользователь, дата проведения, ИНН и взыскатель.
При открытии копируются текущие значения. Изменение фильтров окна не меняет страницу.
Для дат задаётся начало и конец периода через два календаря; в запрос передаётся
тот же диапазон ДД.ММ.ГГГГ-ДД.ММ.ГГГГ, что использует исходная страница.

Ниже расположены три подписанные таблицы: окончание факт и прекращение, окончание
БИ, возбуждение ИП. Каждая строка ищет только в своём типе; заполненные поля
проверяются совместно, строки независимо. Пустые таблицы не запускают поиск.
Порядок полей соответствует реестру, включая скрытый идентификатор записи.
Названия русские. В возбуждении EDNumber подписывается «Номер дела».
Дополнительные поля ответа сервера, отсутствующие среди столбцов страницы,
добавляются в конец: идентификатор реестра, идентификатор электронного документа,
дата добавления; для возбуждения также отдельный DNumber («Номер дела»).
Сохраняются поиск подстроки без учёта регистра, null для пустых значений,
вставка столбца Excel, пауза, ссылки на найденные записи и полный экспорт cell.

Общие фильтры и три таблицы условий раскрываются независимо. После запуска
поиска все четыре блока сворачиваются, освобождая место результатам. Условия
можно раскрыть для просмотра; на время запущенного поиска они зафиксированы.

Окно занимает ширину экрана с небольшими отступами. Каждая таблица имеет свою
горизонтальную прокрутку. Колесо прокручивает область под курсором; при наличии
вертикального переполнения обычное колесо прокручивает её вертикально,
Shift+колесо — горизонтально. Без вертикального переполнения колесо движется
горизонтально. Событие не передаётся соседним областям на границе прокрутки.

В Excel используется общая таблица с русскими заголовками всех известных полей;
различающееся название EDNumber поясняется в заголовке. Неизвестные серверные
поля сохраняются под исходными именами, чтобы не терять данные.

## План и задачи

1. Описать схемы трёх типов и общие фильтры на основе обследованной страницы.
2. Добавить три таблицы, локальную прокрутку и общий фильтр.
3. Ограничить обход и сопоставление типом, перенести русские названия в экспорт.
4. Проверить совместное применение фильтров, разделение типов, вставку, Excel,
   прокрутку и скрытие интерфейса; выполнить проверки staged-файлов и коммит.

## Scope gate

StageTimer — нет. Firefox — общий стандартный DOM-модуль, без специальных API.
Content script и вложенный UI — да. Manifest, permissions, background, состав
ресурсов и деплои — без изменений. deploy.py копирует модуль, deploy-firefox.py
содержит его в списке, deploy_VZID.py поиск ФССП не включает.
Новые блоки вложены в существующее окно с классом скрытия, отдельные пункты F2
не требуются. Постоянные ключи, Supabase и мосты Apps Script/Sheets — нет.

## Быстрый старт

Открыть «Найти ИД в реестрах», выбрать общие фильтры, заполнить строки нужных
типов и нажать «Поиск». В пустом поле ввести null для поиска отсутствующего
значения. Для вставки списка скопировать один столбец Excel. Результаты можно
раскрыть и выгрузить в Excel в процессе поиска или после завершения.

## Проверка

Шесть автоматических проверок: состав и порядок столбцов, совместное сопоставление
значений и null, разделение типов, общие фильтры запросов, даты и содержимое Excel.
В сохранённом Chrome выполнен поиск по реестру 22440: одно совпадение возбуждения,
ноль совпадений в блоке окончания, ошибок нет. Проверены вставка списка, независимая
прокрутка таблиц и результатов, сворачивание и скрытие окна при скриншоте.
Новые постоянные данные не создаются; Supabase-синхронизация не требуется.
