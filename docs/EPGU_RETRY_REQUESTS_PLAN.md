# План: повторные запросы ЕПГУ по неуспешным взыскателям

1. Расширить сбор сегодняшней сводки: сохранять полный текст взыскателя, ФИО и пары,
   которые уже встречались в гриде.
2. Добавить в «Сводку ЕПГУ» кнопку запуска и отдельное окно выбора взыскателей.
3. Сохранять исключённых взыскателей через `DUP_SYNC_SET` и добавить ключ в
   Supabase KV allowlist.
4. Добавить background-команду, которая в MAIN world один раз подтверждает системный
   вопрос и открывает штатную форму создания запроса.
5. Реализовать последовательный исполнитель: открыть форму, выбрать первый новый
   вариант, отправить, дождаться успеха, закрыть форму, перейти дальше.
6. Добавить журнал прогресса, остановку при системной ошибке и пропуск взыскателя без
   свободного ФИО.
7. Обновить стили, F2-описание, глобальную UI-конфигурацию и селекторы скрытия при
   скриншоте.
8. Проверить синтаксис, чистые функции отбора, безопасный DOM-сценарий без реального
   POST, Chrome-контекст и Firefox/deploy scope.
9. Добавить в сводку переключатель баз по департаментам 39, 66 и 70, переходить по
   актуальной ссылке штатного dropdown и одноразово восстанавливать окно после загрузки.
10. Определять активную базу по hostname, добавить вопрос о повторном цикле ФИО и после
    завершения пакета полностью перезагружать страницу с автоматическим возвратом в сводку.
11. Вычислять текущий цикл ФИО по хронологии грида и актуальному списку системной формы,
    чтобы подтверждённый сброс продолжался между повторными запусками.
