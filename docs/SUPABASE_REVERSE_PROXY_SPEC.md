# Спецификация reverse proxy для Supabase

## Пользовательское поведение

Расширение сначала отправляет запросы авторизации, pull, push и Realtime через HTTPS reverse proxy `https://sb.jassco.ru` на VPS. Если VPS временно недоступен или возвращает ошибку шлюза, расширение автоматически пробует прямой адрес проекта Supabase.

Пользователь продолжает работать с тем же Supabase-аккаунтом. Существующая сессия, очередь изменений и серверные данные не переносятся и не преобразуются.

## Требования

- Прокси обслуживает только фиксированный проект `odljanxhmjysnduylvxz` и не является универсальным открытым прокси.
- Пути `/auth/v1/`, `/rest/v1/`, `/realtime/v1/`, `/storage/v1/` и `/functions/v1/` передаются без изменения относительно Supabase API.
- Заголовок `Host` и TLS SNI до upstream соответствуют `odljanxhmjysnduylvxz.supabase.co`.
- Для Realtime поддерживается WebSocket Upgrade и длительное соединение.
- Публикуемый ключ и пользовательский JWT передаются как раньше; закрытые ключи на VPS и в расширение не добавляются.
- Существующие маршруты VPS, сайты и раздача Firefox-сборки не изменяют поведение.

## Область изменений

- Supabase-синхронизация: да.
- Firefox-совместимость: да, общий файл синхронизации используется обеими сборками.
- Background script: да, меняется подключаемый модуль `SupabaseSync/supabase_sync.js`.
- Manifest, permissions, content scripts, UI и селекторы скриншота: нет.
- Новые постоянные ключи хранилища: нет.
- Таблицы, данные и RLS Supabase: нет; серверный allowlist KV-ключей обновляется отдельной миграцией.
- StageTimer, Apps Script и Google Sheets bridge: нет.
