# Импорт архива заявок WSS в Google Sheets

## Спецификация

Цель: добавить в меню Google Sheets по `F2` отдельный блок `Заявки WSS`, чтобы пользователь мог выбрать актуальный `.zip` архив выгрузки WSS и загрузить заявки на лист `WSS`.

Пользовательский сценарий:
1. Пользователь открывает таблицу Google Sheets и нажимает `F2`.
2. В отдельном разделе `Заявки WSS` нажимает `Загрузить архив`.
3. Выбирает `.zip` файл с `.md` заявками и `status_index.xlsx` внутри архива.
4. Расширение разбирает архив, показывает модалку со сводкой и прогрессом.
5. После подтверждения расширение отправляет данные через Apps Script bridge.
6. Bridge добавляет новые строки и обновляет существующие строки на листе `WSS`.

Лист назначения: `WSS`.

Колонки листа:
- `WSS ID`
- `Рег. номер`
- `Краткое описание задачи`
- `Содержание`
- `Расширенная история решений`
- `Доп. файлы`
- `Дата регистрации`
- `Этап`
- `Статус`
- `Призано исполненным`
- `Заказчик`
- `Ответственный`
- `Плановое количество часов`
- `Исполнить до`
- `Комментарий`
- `Номер заявки в СУПП`
- `Состояние заявки в СУПП`
- `Связанные задачи СУПП`
- `last_parsed_at`

`WSS ID` сопоставляется с `wss_id` из `status_index.xlsx` внутри выбранного zip. `last_parsed_at` берется только из `status_index.xlsx` внутри zip.

Если заявка уже есть на листе `WSS`, bridge обновляет строку только когда входящий `last_parsed_at` свежее значения в таблице. Если заявка новая, bridge создает строку и копирует строку 2 как шаблон форматирования.

## Правила парсинга

Метаданные `.md`:
- `WSS ID`, `Рег. номер`, `Дата регистрации`, `Этап`, `Статус`, `Признано исполненным` читаются из блока `## Метаданные заявки`.
- Колонка таблицы `Призано исполненным` заполняется из поля `.md` `Признано исполненным`.

Карточка заявки:
- одноименные `###` блоки переносятся в одноименные колонки;
- fenced-блоки ` ```text ` очищаются от обертки;
- значение `-` считается пустым пользовательским значением и переносится как пустая строка.

Расширенная история решений:
- markdown-таблица из блока `## Расширенная история решений` преобразуется в многострочный текст;
- первая строка каждой записи: `Роль / Пользователь / Решение / Дата / Оповещены`;
- первая строка каждой записи выделяется жирным в ячейке;
- комментарий идет следующей строкой обычным шрифтом;
- если комментария нет, пишется `Комментарий отсутствует`;
- `<br>` внутри таблицы превращается в переносы строк внутри соответствующего поля.

Доп. файлы:
- переносятся только вложения со статусом `ок`;
- вложения со статусами `пропущен`, `ошибка` или без статуса не переносятся;
- каждая запись начинается строкой `Файл <название>`, эта строка выделяется жирным;
- ниже идет извлеченный текст документа обычным шрифтом;
- если извлеченного текста нет, файл не переносится.

Ограничения длины:
- длинные текстовые колонки сокращаются до безопасного лимита для Google Sheets;
- при сокращении добавляется пометка `[текст сокращен]`;
- сокращение применяется к `Содержание`, `Расширенная история решений`, `Доп. файлы`.

## План

1. Добавить блок `Заявки WSS` в меню `F2` перед блоком ChatGPT.
2. Добавить модалку импорта с выбором архива, сводкой и прогрессом.
3. Реализовать локальный парсинг zip и вложенного `status_index.xlsx`.
4. Реализовать парсинг `.md` заявок по заголовкам и таблицам.
5. Добавить bridge-действие `importWssArchiveRows`.
6. На стороне bridge найти существующий лист `WSS`, сопоставить строки по `WSS ID`, обновить только свежие заявки.
7. Для новых строк копировать формат строки 2 и расширять условное форматирование на новые строки, если оно ограничено прежним диапазоном данных.
8. Скрывать WSS-модалку и меню при режиме скриншота.
