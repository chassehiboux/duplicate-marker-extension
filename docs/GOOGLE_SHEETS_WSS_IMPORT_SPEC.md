# Импорт архива заявок WSS в Google Sheets

## Спецификация

Цель: добавить в меню Google Sheets по `F2` отдельный блок `Заявки WSS`, чтобы пользователь мог выбрать актуальный `.zip` архив выгрузки WSS и загрузить заявки на лист `WSS`.

Пользовательский сценарий:
1. Пользователь открывает таблицу Google Sheets и нажимает `F2`.
2. В отдельном разделе `Заявки WSS` нажимает `Загрузить архив`.
3. Выбирает `.zip` файл с `.md` заявками и `status_index.xlsx` внутри архива.
4. Расширение разбирает архив, показывает модалку со сводкой и прогрессом.
5. После подтверждения расширение отправляет данные через Apps Script bridge.
6. Bridge добавляет новые строки и обновляет существующие строки на листе `WSS`.
7. После импорта расширение показывает модалку просмотра созданных и обновленных WSS-заявок.
8. В блоке `Заявки WSS` пользователь может нажать `Поиск заявки`, чтобы отправить компактный CSV листа `WSS` в ChatGPT для смыслового поиска по архиву WSS.

Лист назначения: `WSS`.

Колонки листа:
- `WSS ID`
- `Рег. номер`
- `Краткое описание задачи`
- `Содержание`
- `Расширенная история решений`
- `Доп. файлы`
- `Дата регистрации`
- `Этап`
- `Статус`
- `Призано исполненным`
- `Заказчик`
- `Ответственный`
- `Плановое количество часов`
- `Исполнить до`
- `Комментарий`
- `Номер заявки в СУПП`
- `Состояние заявки в СУПП`
- `Связанные задачи СУПП`
- `last_parsed_at`
- `Пришел новый ответ`
- `Найденный номер заявки в СУПП`
- `Текст найденной заявки в СУПП`

Порядок колонок произвольный: импорт при каждом запуске определяет их позиции по точным
заголовкам строки 1. Недостающие служебные колонки `Пришел новый ответ`,
`Найденный номер заявки в СУПП` и `Текст найденной заявки в СУПП` автоматически добавляются
в конец листа. После этого пользователь может переместить их в любое место. Дублирующиеся
обязательные заголовки считаются ошибкой конфигурации листа.

`WSS ID` сопоставляется с `wss_id` из `status_index.xlsx` внутри выбранного zip. `last_parsed_at` берется только из `status_index.xlsx` внутри zip.

Если заявка уже есть на листе `WSS`, bridge обновляет строку, когда входящий `last_parsed_at`
свежее значения в таблице или в истории обнаружена строго более поздняя запись. Если заявка
новая, bridge записывает её в свободную строку и копирует формат фиксированно из строки 2. Если
на листе ещё нет WSS-заявок, первая новая заявка записывается прямо в строку 2.

При обновлении существующей заявки bridge изменяет только архивные WSS-колонки. Значения,
формулы и оформление дополнительных пользовательских колонок не перезаписываются. Колонки
`Найденный номер заявки в СУПП` и `Текст найденной заявки в СУПП` всегда сохраняются без
изменений; для новой строки они остаются пустыми и предназначены для отдельной будущей
обработки. Существующая колонка `Номер заявки в СУПП` остаётся архивной и продолжает
заполняться из одноимённого блока MD.

Перед обновлением существующей строки bridge находит максимальную дату со временем в старой
и входящей `Расширенной истории решений`. Распознаются заголовки записей вида
`дд.мм.гггг чч:мм / ...` и `дд.мм.гггг чч:мм:сс / ...`; даты внутри комментариев не
учитываются. Порядок записей истории значения не имеет. Если входящая максимальная дата строго
новее сохранённой, ячейка `Пришел новый ответ` окрашивается в `#00ff00`. Первая датированная
запись у уже существующей заявки также считается новым ответом. Новая заявка при первичной
загрузке не подсвечивается. Равная или более старая дата новую подсветку не создаёт, а уже
существующая зелёная подсветка сохраняется до ручного снятия.

После завершения импорта модалка просмотра WSS показывает все строки, которые bridge реально создал или обновил. При повторном импорте, когда новых WSS ID нет, но `last_parsed_at` свежее, в модалке показываются обновленные заявки.

## Правила парсинга

Метаданные `.md`:
- `WSS ID`, `Рег. номер`, `Дата регистрации`, `Этап`, `Статус`, `Признано исполненным` читаются из блока `## Метаданные заявки`.
- Колонка таблицы `Призано исполненным` заполняется из поля `.md` `Признано исполненным`.

Карточка заявки:
- одноименные `###` блоки переносятся в одноименные колонки;
- fenced-блоки ` ```text ` очищаются от обертки;
- значение `-` считается пустым пользовательским значением и переносится как пустая строка.

Расширенная история решений:
- markdown-таблица из блока `## Расширенная история решений` преобразуется в многострочный текст;
- первая строка каждой записи: `Дата / Пользователь → Оповещены`;
- первая строка каждой записи выделяется жирным шрифтом 11 пт;
- следующей строкой идет `Решение` жирным шрифтом;
- комментарий идет следующей строкой обычным шрифтом;
- если комментария нет, пишется `комментария нет`;
- `<br>` внутри таблицы превращается в переносы строк внутри соответствующего поля.

Доп. файлы:
- переносятся только вложения со статусом `ок`;
- вложения со статусами `пропущен`, `ошибка` или без статуса не переносятся;
- каждая запись начинается строкой `Файл <название>`, эта строка выделяется жирным;
- ниже идет извлеченный текст документа обычным шрифтом;
- если извлеченного текста нет, файл не переносится.

Ограничения длины:
- длинные текстовые колонки сокращаются до безопасного лимита для Google Sheets;
- при сокращении добавляется пометка `[текст сокращен]`;
- сокращение применяется к `Содержание`, `Расширенная история решений`, `Доп. файлы`.

## План

1. Добавить блок `Заявки WSS` в меню `F2` перед блоком ChatGPT.
2. Добавить модалку импорта с выбором архива, сводкой и прогрессом.
3. Реализовать локальный парсинг zip и вложенного `status_index.xlsx`.
4. Реализовать парсинг `.md` заявок по заголовкам и таблицам.
5. Добавить bridge-действие `importWssArchiveRows`.
6. На стороне bridge найти существующий лист `WSS`, сопоставить строки по `WSS ID`, обновить только свежие заявки.
7. Для новых строк копировать формат строки 2 и расширять условное форматирование на новые строки, если оно ограничено прежним диапазоном данных.
8. Показывать модалку просмотра созданных и обновленных WSS-заявок после импорта.
9. Добавить кнопку `Поиск заявки` для отправки компактного CSV листа `WSS` в ChatGPT.
10. Скрывать WSS-модалки и меню при режиме скриншота.
11. Добавить управляемые по заголовкам служебные колонки WSS и разрешить их произвольное расположение.
12. Обновлять только архивные колонки, не затрагивая пользовательские поля и формулы.
13. Сравнивать максимальную дату расширенной истории до перезаписи строки и подсвечивать новые ответы.

## Задачи проверки

1. Проверить синтаксис `GoogleSheets/problem_picker_content.js`.
2. Проверить синтаксис `GoogleSheets/problem_picker_background.js`.
3. Проверить синтаксис `GoogleSheets/GoogleAppsScript/ProblemPickerBridge.gs`.
4. Проверить staged diff и состав коммита.
5. Выполнить точечную UTF-8/mojibake-проверку измененных файлов с русским текстом.

## Быстрая проверка

1. Переместить архивные и служебные колонки WSS в произвольном порядке и импортировать архив.
2. Убедиться, что данные попали в колонки с соответствующими заголовками.
3. Заполнить `Найденный номер заявки в СУПП` и `Текст найденной заявки в СУПП`, затем повторно
   импортировать более свежую версию той же заявки и проверить сохранность значений.
4. Для существующей заявки загрузить историю с более поздней записью и проверить зелёный фон
   `Пришел новый ответ`.
5. Повторить импорт без более поздней записи и убедиться, что новая подсветка не появляется,
   а ранее установленная не снимается.
6. Импортировать новую заявку с заполненной историей и убедиться, что при первом добавлении она
   не помечается как новый ответ.
7. Добавить пользовательскую колонку с формулой и проверить, что обновление WSS её не изменило.
