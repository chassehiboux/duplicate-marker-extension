# Классификация заявок через расширение

## Спецификация

Цель: заменить медленную HtmlService-модалку `problemPicker.html` локальной модалкой расширения на странице Google Sheets и вынести действия модуля в меню расширения по `F2`.

Таблица: `1A7bsMpcMegLvTIpdRBa06TD5RxGi64Cw3goYydbujNo`.

Код расширения вынесен в отдельный блок:
- `GoogleSheets/problem_picker_config.js`
- `GoogleSheets/problem_picker_content.js`
- `GoogleSheets/problem_picker_background.js`

Модуль подключается отдельной записью `content_scripts` только для URL:

`https://docs.google.com/spreadsheets/d/1A7bsMpcMegLvTIpdRBa06TD5RxGi64Cw3goYydbujNo/*`

Листы для классификации:
- `Заявки`
- `Заявки (наши)`

Колонки определяются по заголовкам:
- `Текст заявки`
- `Проблемы`
- `Дата заявки`
- `Статус заявки`
- `Инициатор`
- `Номер ITIL`
- `Номер СУПП (последний)`
- `Информация из СУПП/ITIL`
- `Избранное`

Очередь формируется в расширении по CSV-экспорту активного листа: берутся строки, где `Текст заявки` заполнен, а `Проблемы` пустая. На реальной таблице проверено: экспорт листа `Заявки` возвращает 2545 строк, `Проблемы` находится в колонке B, `Текст заявки` в колонке T.

## Ограничение записи

Запись через UI Google Sheets не используется. На реальной таблице включён фильтр: при переходе к `B2021` интерфейс выбрал `B2029`, поэтому автоматическая вставка через DOM может записать значение в неверную строку.

Для сохранения используется лёгкий Apps Script bridge:
- расширение показывает модалку, хранит очередь и быстро переключает заявки;
- bridge принимает `sheetName`, `row`, `value`;
- bridge сохраняет категорию и принимает уже очищенный расширением текст заявки, чтобы Apps Script не зависел от серверной функции очистки текста.

В сводке модалки по каждой строке показываются `Номер строки`, `Дата заявки`, `Статус заявки`, `Инициатор`, `Номер ITIL` и связанные заявки СУПП. Для `Статус заявки` и `Инициатор` расширение дополнительно подтягивает цвет заливки ячейки из таблицы, чтобы пользователь видел тот же визуальный сигнал, что и в листе.

Для `Номер ITIL` в шапке сводки доступны две кнопки действий:
- слева `Открыть заявку`;
- справа `Копировать`.

Для СУПП сводка показывает отдельный список связанных заявок:
- сверху находится самая последняя заявка из ячейки `Номер СУПП (последний)`;
- у каждой строки списка есть свои кнопки `Открыть` и `Копировать`;
- самая последняя заявка дополнительно помечается бейджем `последняя`.

Кнопка `Открыть заявку` переключает пользователя на соответствующую вкладку ITIL или СУПП, выполняет поиск и открывает карточку заявки. Кнопка `Копировать` остаётся на текущем месте и продолжает работать как раньше.

Блок `Информация из СУПП/ITIL` в модалках рисуется не как сплошной plain text: каждая секция `ИТИЛ` или отдельной заявки СУПП показывается своей шапкой, строки журналов вида `дата / автор / ...` выделяются как заголовки записей, а многострочное содержимое записи остаётся внутри того же блока даже при наличии пустых строк и списков.

Если для одной строки есть несколько заявок СУПП, модалка показывает отдельные секции по каждой из них в порядке “снизу вверх” относительно ячейки `Номер СУПП (последний)`, то есть первой идёт самая последняя заявка.

Если заявка СУПП не найдена, её секция в модалке выделяется как предупреждение и ниже показывает решение из ITIL с явной подписью, что это fallback из ITIL.

Если в обсуждении СУПП есть цитата, расширение сохраняет её в тексте `Информация из СУПП/ITIL` построчно с явным служебным префиксом глубины вида `[[Q1]]`, `[[Q2]]` и т.д. Это позволяет точно отличать цитату от обычного текста и в модалке рисовать её отдельным вложенным quote-блоком.

## План

1. Добавить отдельное меню расширения по `F2` на странице указанной таблицы.
2. Загружать CSV активного листа через `fetch(..., { credentials: 'omit' })`.
3. Показывать локальную модалку классификации с теми же вариантами проблем.
4. Сохранять выбор через bridge URL, заданный кнопкой `URL bridge` в меню `F2`.
5. Скрывать элементы модалки при создании скриншота.
6. Форматировать `Текст заявки` на стороне расширения до отправки в bridge.

## Меню F2

На странице Google Sheets модуль показывает отдельное меню по `F2`.

Во вкладке `Функции`:
- `Поиск новых заявок, классификация, новые ответы` содержит кнопки `Старт`, `Стоп`, `Непрочитанные (N)`, `▼` и `URL bridge`.
- `Старт` запускает единый сценарий: расширение одним общим циклом ищет пустой `Текст заявки` и для строк ITIL, и для строк СУПП, затем сразу открывает классификацию и параллельно запускает обработку блока `Пришел новый ответ`.
- Классификация в этом сценарии показывает всю текущую очередь строк, где `Текст заявки` заполнен, а `Проблемы` пустая, а не только строки текущего запуска.
- После завершения классификации расширение автоматически переводит пользователя в модалку `Новые ответы`; если фоновой обработке ещё нужно время, модалка открывается в режиме ожидания.
- `Непрочитанные (N)` загружает постоянную очередь новых ответов из скрытого системного листа Google Sheets. Очередь сохраняется после закрытия модалки, вкладки и браузера.
- `▼` раскрывает ручные действия: `Классификация`, `ITIL: заполнить текст заявок`, `СУПП: заполнить текст заявок` и `Пришел новый ответ`.
- `URL bridge` задаёт URL Apps Script Web app для записи в таблицу.
- `Поиск заявки через ChatGPT` открывает локальную модалку, где пользователь может:
  - в режиме `Поиск заявки` ввести свободный запрос для поиска по заявкам;
  - в режиме `Задать вопрос по заявкам` отправить в ChatGPT вопрос с тем же CSV и готовым исследовательским промптом, чтобы продолжить анализ уже прямо во вкладке ChatGPT.

## Поиск заявок через ChatGPT

Сценарий нужен, чтобы пользователь оставался на листе `Заявки`, а расширение само выполняло весь путь поиска:
1. Пользователь открывает `F2`, выбирает `Поиск заявки через ChatGPT` и вводит произвольный текстовый запрос.
2. Расширение выгружает лист `Заявки` в CSV и собирает компактный файл только из колонок:
   - служебный `__row_id` для точного возврата найденных строк;
   - `Дата заявки`;
   - `Статус заявки`;
   - `Проблемы`;
   - `Инициатор`;
   - `Номер ITIL`;
   - `Номер СУПП (последний)`;
   - `Текст заявки`;
   - `Информация из СУПП/ITIL`.
3. В фоне открывается новый временный чат `https://chatgpt.com/?temporary-chat=true`, туда прикрепляется CSV, вставляется пользовательский запрос и служебный промпт, после чего запрос отправляется автоматически.
4. ChatGPT делает смысловой отбор заявок: главным источником смысла служит `Текст заявки`, вторым — `Информация из СУПП/ITIL`, остальные колонки используются только как вспомогательные признаки.
5. В ответе ChatGPT возвращает только JSON со списком найденных `__row_id` и необязательными пояснениями совпадений. Исходные строки он не перепечатывает.
6. Расширение само собирает точную итоговую таблицу из исходного CSV и через bridge записывает её на отдельный временный лист `Поиск заявок (ИИ)`. Лист каждый раз пересоздаётся из скрытого шаблона `Шаблон (Поиск заявок (ИИ))`, а формат строк заявок тиражируется по образцу второй строки; справа от исходных колонок добавляется `Пояснение совпадения`, если ChatGPT его вернул.

Так обязательные значения на результирующем листе остаются ровно такими, какими были в исходном CSV, а ChatGPT используется именно для смыслового поиска, а не для повторного переписывания данных.

## Вопрос по заявкам через ChatGPT

Рядом с `Поиск заявки` в том же блоке меню есть отдельная кнопка `Задать вопрос по заявкам`.

Сценарий нужен, когда пользователю не требуется автоматическая запись результата в Google Sheets:
1. Пользователь открывает `F2`, выбирает `Задать вопрос по заявкам` и вводит вопрос по существующим заявкам.
2. Расширение выгружает тот же компактный CSV по листу `Заявки`, что и для поиска.
3. В фоне открывается новый временный чат `https://chatgpt.com/?temporary-chat=true`, туда прикрепляется CSV, вставляется вопрос пользователя и служебный промпт для глубокого анализа только по данным CSV.
4. После отправки сообщения расширение не ждёт финального ответа и не записывает результат в таблицу.
5. Пользователь продолжает работу уже в открытой вкладке ChatGPT, где может читать ответ, задавать уточнения и развивать анализ в пределах этого временного чата.

Промпт для этого режима требует:
- использовать только данные приложенного CSV;
- давать развернутый аналитический ответ в стиле глубокого исследования;
- для каждого существенного вывода приводить ссылки на конкретные заявки и короткие цитаты;
- ссылаться сначала на `Номер СУПП (последний)`, а если там `–` или пусто, то на `Номер ITIL`.

## Единый цикл поиска, классификации и новых ответов

Сценарий нужен, чтобы пользователь одним запуском получал сразу весь рабочий поток без ручного переключения между отдельными кнопками:
1. Пользователь открывает `F2` и нажимает `Старт` в блоке `Поиск новых заявок, классификация, новые ответы`.
2. Расширение собирает общую очередь строк с пустым `Текст заявки` и обрабатывает их в порядке строк листа:
   - если у строки ветка ITIL, используется тот же поиск по ITIL;
   - если у строки ветка СУПП, используется тот же поиск по СУПП.
3. После завершения общего поиска расширение дожидается отправки найденных данных в bridge и сразу открывает модалку классификации.
4. В этот же момент в фоне стартует сценарий `Пришел новый ответ`, но он не перекрывает модалку классификации.
5. Модалка классификации показывает всю текущую очередь строк, где `Текст заявки` уже заполнен, а `Проблемы` ещё пустая, включая строки, которые были в очереди до запуска общего сценария.
6. Когда пользователь заканчивает классификацию последней строки, расширение автоматически переключает его в модалку `Новые ответы`.
7. Если фоновые новые ответы к этому моменту уже готовы, открывается очередь просмотра сохранённых изменений; если обработка ещё идёт, модалка открывается в режиме ожидания и продолжает обновляться сама.
8. Если новых строк для классификации нет, переход к модалке `Новые ответы` выполняется сразу после общего поиска.
9. Каждый успешно сохранённый новый ответ добавляется в постоянную очередь и доступен через `Непрочитанные (N)` до явного подтверждения прочтения.

## Навигация в модалках

### Избранное

В правом верхнем углу модалок классификации и новых ответов находится кнопка-звезда. Неактивная звезда добавляет текущую заявку в избранное, записывает `Да` в колонку `Избранное` и подсвечивает основные поверхности модалки мягким жёлтым цветом. Активная звезда снимает избранное, полностью очищает ячейку и возвращает обычный фон.

Источник истины — исходная строка листа `Заявки` или `Заявки (наши)`: отдельное состояние в браузере и скрытой очереди не хранится. Поэтому ручное удаление `Да` из таблицы считается снятием избранного и отражается после следующей загрузки классификации или повторного открытия непрочитанных ответов. Перед записью bridge сверяет идентификаторы заявки, чтобы не изменить другую строку после сортировки или вставки строк.

### Классификация

В модалке классификации доступны:
- `Назад` для возврата к предыдущей заявке;
- `Закрыть`;
- список категорий.

Поведение `Назад`:
- если пользователь находится на заявке `20` и нажимает `Назад`, открывается заявка `19`;
- если пользователь меняет категорию у `19`, после сохранения расширение возвращает его на `20`;
- при возврате на уже сохранённую строку модалка показывает текущую сохранённую категорию как явное состояние интерфейса.

### Новые ответы

В модалке `Новые ответы` доступны:
- `Закрыть`.
- одна кнопка `Прочитано и дальше`, которая на последней карточке называется `Прочитано и закрыть`.

`Закрыть` не меняет очередь. `Прочитано и дальше` сразу удаляет текущую карточку из скрытого системного листа и показывает следующий непрочитанный ответ. Прочитанные карточки и отдельный архив не хранятся.

## Заполнение текста из ITIL

Очередь ITIL формируется из CSV активного листа `Заявки` или `Заявки (наши)` по заголовкам:
- `Номер ITIL`
- `Номер СУПП (последний)`
- `Текст заявки`

В очередь попадают строки, где `Номер СУПП (последний)` равен `–`, `Текст заявки` пустой, а `Номер ITIL` заполнен.

Процесс:
1. Проверить наличие вкладки `http://tmn-vpitil1c01/ITIL/ru_RU/`; если её нет, открыть.
2. Дождаться личного кабинета и открыть `Service Desk`, если вкладка ещё не открыта.
3. Для каждого номера ITIL очистить поле поиска Service Desk и вставить номер как пользовательская вставка через `Ctrl+V`/paste-сценарий.
4. Дождаться единственной найденной строки, открыть заявку двойным кликом.
5. Считать текст из iframe полного текста/переписки и значение поля `Решение обращения`.
6. Очистить текст заявки той же логикой, которая раньше была в `Code.gs`: взять первый ITIL-комментарий между строками автора, а если найдена только одна авторская строка, взять текст после неё до конца; убрать строки с именами файлов, вырезать блок по маркерам `Детальное описание:` / `Причина возникновения инцидента:`, удалить `ЗНО ...`, нормализовать пробелы и пустые строки.
7. Записать в таблицу:
   - `Текст заявки` = отформатированный текст из ITIL;
   - `Информация из СУПП/ITIL` = `ИТИЛ\n\n` + текст решения.
8. Закрыть вкладку заявки и перейти к следующему номеру.

Дополнительно эта же логика поиска и открытия заявки используется кнопкой `Открыть заявку` из модалок Google Sheets. В этом сценарии вкладка ITIL не закрывается после открытия карточки: пользователь сразу переключается на неё и остаётся в открытой заявке.

Кнопка `Стоп` прекращает дальнейшую обработку и сбрасывает runtime-состояние очереди. Долговечные ключи `chrome.storage.local` для ITIL-очереди не используются.

Для Firefox перед поиском расширение дополнительно кладёт номер ITIL в системный clipboard и пробует paste-команду во вкладке ITIL. Если браузер блокирует настоящий paste в поле ввода, используется fallback с заменой выделенного текста, событиями `input/change` и `Enter`.

## Заполнение текста из СУПП

Очередь СУПП формируется из CSV активного листа `Заявки` или `Заявки (наши)` по заголовкам:
- `Номер СУПП (последний)`
- `Текст заявки`
- `Информация из СУПП/ITIL`

В очередь попадают строки, где `Текст заявки` пустой, а в `Номер СУПП (последний)` есть хотя бы одна непустая строка, кроме `–`, `—` и `-`.

Парсинг ячейки `Номер СУПП (последний)`:
- каждая строка ячейки считается отдельной связанной заявкой;
- дубли удаляются;
- порядок обработки и показа разворачивается так, чтобы первой шла последняя строка ячейки;
- формат номера не ограничен префиксом `ЗНР-`, поэтому поддерживаются и другие варианты, например `ПКП-...`.

Процесс:
1. Проверить наличие вкладки `http://tmn-vpsupp1c01.corp.vostok-electra.ru/PMS/ru_RU/`; если её нет, открыть неактивной вкладкой.
2. Из ячейки собирается список всех связанных заявок СУПП. Самая последняя заявка списка становится основной.
3. Для каждого номера СУПП очистить глобальное поле поиска `Поиск Ctrl+Shift+F`, закрыть выпадающую выдачу и ввести номер.
4. Если поиск показывает, что заявка не найдена, полностью очистить поле, закрыть поиск и повторить ввод номера один раз.
5. Дождаться строки `Заявка <номер СУПП>` в выдаче и открыть карточку кликом.
6. Считать полный текст iframe `ИнформацияПоЗаявке`, отдельно взять из него раздел `Комментарии` до разделов `Файлы`/`Дополнительно`.
7. Открыть панель `Обсуждение`, считать сообщения из `VW_page1ecsCell`.
8. Записать в таблицу:
   - если в строке одна заявка СУПП, `Текст заявки` по умолчанию берётся из СУПП, но если заявка не нашлась или в описании СУПП найден `ЗНО ...`, используется ITIL текущей строки;
   - если в строке несколько заявок СУПП, `Текст заявки` всегда берётся из ITIL текущей строки;
   - `Информация из СУПП/ITIL` содержит отдельные секции по всем заявкам СУПП;
   - только у самой последней заявки сохраняется блок `Причина возникновения инцидента`;
   - у остальных заявок сохраняются комментарии и обсуждение;
   - если конкретная заявка не найдена, для неё сохраняется предупреждение `Не найдена заявка в СУПП. Проверьте вручную`, а ниже добавляется `Решение обращения (ITIL)` и `Дополнительная информация (ITIL)` из текущего ITIL.
9. Закрыть карточку заявки через `VW_page1headerTopLine_cmd_CloseButton`, очистить глобальный поиск и перейти к следующему номеру.

Кнопка `Тест 1 заявка` запускает тот же процесс, но обрабатывает только первую строку очереди и останавливается. Кнопка `Стоп` прекращает дальнейшую обработку и сбрасывает runtime-состояние очереди.

Если в строке только одна заявка СУПП и после повторной попытки она не появилась в выдаче или поиск вернул, что она не найдена, строка не пропускается: `Текст заявки` берётся из ITIL, а в `Информация из СУПП/ITIL` сохраняется предупреждение по СУПП и решение из ITIL.

Если в строке несколько заявок СУПП, ошибка поиска по одной заявке не останавливает обработку всей строки: для такой заявки создаётся предупреждающая секция, а остальные заявки продолжают обрабатываться.

Вкладки ITIL и СУПП при работе не делаются принудительно активными: если вкладка уже открыта, скрипт выполняется в ней в фоне; если вкладки нет, она создаётся как неактивная.

Дополнительно эта же логика поиска и открытия заявки используется кнопкой `Открыть заявку` из модалок Google Sheets. В этом сценарии вкладка СУПП активируется, поиск открывает карточку и оставляет пользователя внутри неё без автоматического закрытия.

Формат `Информация из СУПП/ITIL`:
- строка номера СУПП выделяется жирным 11;
- служебные заголовки `Причина возникновения инцидента`, `Решение обращения` и `Дополнительная информация`, включая fallback-варианты `(ITIL)`, выделяются жирным;
- строки-шапки вида `DD.MM.YYYY H:mm:ss / ...` выделяются жирным;
- остальной текст остаётся обычным 10;
- в конце ячейки сохраняется пустая строка.

## Пришел новый ответ

Очередь формируется через Apps Script bridge, потому что CSV-экспорт Google Sheets не содержит заливку ячеек. Bridge читает фон колонки `Пришел новый ответ` и возвращает только строки, где фон равен `#00ff00`.

Для каждой найденной строки обновляется только `Информация из СУПП/ITIL`:
- если в `Номер СУПП (последний)` есть один или несколько номеров, используется ветка СУПП;
- если в `Номер СУПП (последний)` записано ровно `–`, `—` или `-`, используется ветка ITIL;
- если по значению колонки нельзя выбрать ветку, обработка останавливается с ошибкой по конкретной строке.

`Текст заявки` в этом сценарии не меняется. Перед обновлением INFO bridge создаёт в скрытом листе `Служебные новые ответы` постоянную карточку со снимками старого и нового INFO. После успешной записи bridge сбрасывает цвет в `Пришел новый ответ` и `Номер СУПП (последний)`.

Системная карточка позволяет заново построить подсветку новых блоков без повторного поиска по ITIL или СУПП. Технический повтор того же сохранения определяется по стабильному идентификатору и не создаёт дубль. Разные обновления одной заявки сохраняются отдельными карточками, пока пользователь их не прочитает.

Если операция прервалась после создания системной карточки, но до завершения обновления строки, следующий запрос bridge восстанавливает незавершённую запись. Новые ключи локального хранилища браузера и Supabase для этой очереди не используются.

Если строка идёт по ветке СУПП и в ней несколько связанных заявок:
- расширение обновляет все секции этой строки;
- если поиск явно показал, что конкретная заявка не найдена в СУПП, её секция перезаписывается предупреждением и решением из ITIL;
- если одна из заявок временно не нашлась и это не сценарий `не найдена`, уже существующая секция этой заявки сохраняется без перезаписи;
- если прошлой секции не было, создаётся предупреждающая секция;
- модалка новых ответов показывает итог по строке в формате количества обновлённых заявок.

## Быстрый старт

1. Добавить файл `ProblemPickerBridge.gs` в Apps Script проект таблицы.
2. Задеплоить Apps Script как Web app.
3. Открыть таблицу, нажать `F2` и выбрать `URL bridge`.
4. Вставить URL Web app вида `https://script.google.com/macros/s/.../exec`.
5. Для основного сценария нажать `F2` и `Старт` в блоке `Поиск новых заявок, классификация, новые ответы`; для резервного ручного режима раскрыть `▼` и выбрать `Классификация`, `ITIL`, `СУПП` или `Пришел новый ответ`.
