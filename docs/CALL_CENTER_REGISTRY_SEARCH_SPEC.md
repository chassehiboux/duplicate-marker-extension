# Поиск в реестрах взыскания колл-центра

## Цель

На странице `/call-center/reestrs/view?section=debt_claim` в нижней панели списка
добавляется кнопка «Найти в реестрах». Она открывает пакетный поиск абонентов по всем
созданным реестрам раздела «Уведомления о взыскании задолженности».

## Поля поиска

Одна строка объединяет шесть условий:

- ЛС (`AccountNumber`);
- номер телефона (`PhoneNumber`);
- адрес (`FullAddress`);
- ФИО абонента (`AbonentFullName`);
- номер ИД (`EDNumber`);
- тип взыскания (`SolidarityType`).

Заполненные поля одной строки применяются совместно. После заполнения последней строки
автоматически появляется следующая пустая строка.

## Получение данных

Поиск использует штатный JSON-адрес `/call-center/tasks/data?section=debt_claim` и
серверные jqGrid-фильтры с операцией «содержит». Для каждой строки критериев проверяются
три состояния задач: `queue`, `work` и `archive`. Ответы читаются постранично, поэтому
расширение не загружает целиком тысячи неподходящих записей.

Во время поиска доступна кнопка «Стоп». Уже начатый запрос может завершиться, но новые
страницы и состояния не запускаются. Кнопка меняется на «Продолжить» и возобновляет тот
же поиск с сохранёнными результатами. Закрытие окна полностью отменяет поиск.

## Результаты

Каждая найденная задача отображается отдельной строкой сразу после получения страницы.
Таблица содержит фактические значения полей поиска и дополнительный столбец «№ реестра».
Номер реестра является ссылкой на точное состояние найденной задачи.

После перехода по ссылке расширение увеличивает размер страницы реестра, находит строку
по `CallCenterTaskID`, прокручивает к ней и трижды подсвечивает зелёным.

## Интерфейс и хранение

Окно занимает почти всю высоту экрана. Форма поиска остаётся сверху, затем идут кнопки и
прогресс, а таблица результатов занимает всё свободное место и прокручивается отдельно.
Интерфейс скрывается при создании скриншота и имеет отдельный пункт в меню F2.

Критерии и результаты существуют только в открытом окне. Новый постоянный ключ видимости
`dup_ui_show_call_center_registry_search` синхронизируется существующим механизмом
Supabase для префикса `dup_ui_show_`; других постоянных данных нет.
