# Google Sheets Multi SUPP Spec

## Цель

Сделать так, чтобы одна строка Google Sheets могла содержать несколько связанных заявок СУПП в ячейке `Номер СУПП (последний)`, а расширение обрабатывало их все без ручного копирования и повторных запусков.

Результат для пользователя:

- если в ячейке несколько номеров заявок, расширение считает их отдельными связанными заявками;
- `Текст заявки` для такой строки всегда берётся из ITIL;
- `Информация из СУПП/ITIL` содержит отдельные секции по каждой заявке СУПП;
- сверху показывается самая последняя заявка из ячейки, ниже более ранние;
- `Причина возникновения инцидента` берётся только из самой последней заявки;
- если одна из заявок не найдена в СУПП, для неё всё равно создаётся отдельный блок с явным предупреждением и решением из ITIL;
- сценарий `Пришел новый ответ` обновляет все заявки СУПП строки, а не одну последнюю.

## Источник номеров СУПП

Ячейка `Номер СУПП (последний)` больше не парсится по префиксу `ЗНР-`.

Правило извлечения:

- каждая непустая строка ячейки считается номером заявки;
- строки `–`, `—` и `-` игнорируются;
- пробелы по краям обрезаются;
- дубли удаляются с сохранением исходного порядка;
- для отображения и обработки список разворачивается, чтобы первой шла последняя строка ячейки.

Это должно поддерживать номера вида:

- `ЗНР-С-ПКП18-0000000000805`;
- `ЗНР-С-АИС20-0000000006944`;
- `ПКП-000000022450`;
- и другие форматы, если они записаны отдельными строками.

## Первичное заполнение из СУПП

Если у строки пустой `Текст заявки`, но в ячейке `Номер СУПП (последний)` есть один или несколько номеров:

1. Расширение извлекает весь список заявок.
2. `Текст заявки` получает из ITIL текущей строки.
3. Для каждой заявки СУПП расширение открывает карточку и собирает данные.
4. В `Информация из СУПП/ITIL` записываются отдельные секции по всем заявкам:
   - у самой последней заявки: причина инцидента, комментарии и обсуждение;
   - у остальных заявок: комментарии и обсуждение без блока причины.
5. Если заявка не найдена в поиске СУПП, для неё создаётся секция:
   - заголовок с номером заявки;
   - текст `Не найдена заявка в СУПП. Проверьте вручную`;
   - ниже блоки `Решение обращения (ITIL)` и `Дополнительная информация (ITIL)` из текущего ITIL строки.

Строка не должна пропускаться целиком из-за одной не найденной связанной заявки.

## Новые ответы

Если строка помечена как `Пришел новый ответ` и у неё есть список заявок СУПП:

- обновляются все секции СУПП этой строки;
- порядок секций остаётся тем же: сверху последняя заявка;
- если поиск явно показал, что конкретной заявки больше нет в СУПП, её секция заменяется предупреждением и решением из ITIL;
- если часть заявок обновилась, а часть временно нет, успешные секции сохраняются, а проблемные остаются с предыдущими данными или получают предупреждение, если данных раньше не было;
- модалка должна показывать результат по строке с количеством обновлённых заявок.

Если у строки `Номер СУПП (последний)` содержит только `–`, поведение ITIL остаётся прежним.

## Модалки

В сводке строки:

- вместо одного значения `Номер СУПП (последний)` показывается список связанных заявок;
- у каждого номера есть своя кнопка открытия;
- первой показывается последняя заявка.

В блоке `Информация из СУПП/ITIL`:

- каждая заявка СУПП рисуется отдельной секцией;
- секция с предупреждением о ненайденной заявке визуально отличается от обычной и показывает, что последующая информация взята из ITIL;
- логика отображения `ИТИЛ` остаётся совместимой с текущим форматом.
