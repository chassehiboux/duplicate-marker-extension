# Большие результаты поиска ИД

В Excel для каждой найденной строки добавлен отдельный столбец «Имя файла (FileName)».
Значение берётся из FileName реестра и сохраняется вместе с совпадением при переходах
между департаментами. Для старых снимков используется FileName самой строки, если он
присутствует; отсутствующее имя остаётся пустым. Для полного заполнения нужен новый поиск.
Scope этой правки: данные совпадения и Excel, без нового UI, постоянных ключей,
Supabase, StageTimer, permissions или состава сборки. Данные временные локальные,
передаются существующим механизмом сохранения поиска и выгружаются в Excel.

## Продолжение при временных сбоях сервера

Цель: полностью проверить выбранные реестры и департаменты. Обрыв соединения,
тайм-аут, HTTP 408/429 и 5xx не завершают поиск: повторяется тот же запрос
с задержкой от 1 до 30 секунд, без пропуска реестра. Зависший запрос ограничен
45 секундами. В ожидании показывается причина и номер повторной попытки.
Пауза сохраняет своё поведение; отмена прекращает запрос и ожидание повтора.
HTTP 4xx, кроме 408/429, и страница входа требуют устранения причины;
их нельзя выдавать за успешно прочитанные реестры.
Scope: только запросы content script и регрессионные тесты, без новых данных,
UI-элементов, permissions, StageTimer, Supabase и изменений сборки.

## Сохранение больших результатов и понятный итог

План исправления ошибки 64 MiB: передавать снимок поиска частями по 256 К символов,
хранить части в IndexedDB расширения, а в storage.session — только указатель.
Подтверждать новый снимок лишь после записи всех частей; незавершённая запись
не заменяет предыдущий снимок. Чтение также выполняется частями.
Очистка: закрытие вкладки, завершение поиска, срок 12 часов и потеря браузерной сессии.
Это временные результаты конкретного поиска, только локальные, без Supabase-синхронизации.

Окно и сообщение после выгрузки должны отличать полный результат от частичного.
При ошибке остаются доступны найденные строки и явно указано, что поиск прерван.
Проверки: передача более 64 MiB, неполная запись, восстановление после перезапуска
фонового обработчика, изоляция вкладок, очистка и сообщения итогового статуса.

Scope дополнен фоновой логикой поиска; обе основные сборки уже подключают модуль.
StageTimer не содержит поиск ИД. Новых файлов исполнения, permissions и зависимостей нет.

Реализовано: части по 256 К символов, атомарное переключение указателя после полной
записи, очередь сохранений и очистки, чтение частями и совместимость со старыми
небольшими снимками. Временные части очищаются при закрытии вкладки, завершении,
истечении срока при следующем обращении и запуске фонового обработчика. Части,
оставшиеся от прошлой браузерной сессии, удаляются при запуске обработчика.
Ошибка записи запрещает переход, найденные строки остаются в окне для выгрузки.
Имя Excel содержит «полный» или «частичный»; уведомление после выгрузки сохраняет
этот статус. Ошибка очистки уже завершённого поиска не меняет результат на частичный.

Тесты больших снимков используют временную библиотеку fake-indexeddb вне репозитория.
Для их запуска задаётся FSSP_TEST_IDB_MODULE с абсолютным путём к её каталогу и
выполняется node --test FsspRegistrySearch/fssp_registry_search_background.test.cjs.
Без этой переменной два интеграционных теста явно пропускаются.
Проверено 33188 совпадений с данными более 64 MiB, ограничение размера сообщений,
восстановление после перезапуска обработчика, незавершённая запись, изоляция вкладок,
очистка частей и смена браузерной сессии. На живом сайте большой поиск не запускался.

Основание выбора хранилища: IndexedDB доступна фоновому обработчику расширения:
https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies

Исправление зависания после проверки 1315 реестров и получения 21469 совпадений.
Причина в коде: после каждого пополнения результатов все строки группы создавались
заново, включая свёрнутые группы. Количество ячеек в документе росло без ограничения.

Теперь свёрнутые группы содержат только заголовок; открытые показывают по 100 строк
с кнопками «Назад» и «Далее», общим количеством страниц и сквозной нумерацией.
Все совпадения остаются доступными для просмотра и полной выгрузки в Excel.
При закрытии группы её строки удаляются из документа.

Область: отображение результатов существующего content script, элементы управления
внутри уже скрываемого при скриншоте окна. Новых пунктов F2 и самостоятельных
элементов расширения нет. StageTimer, постоянные ключи, Supabase, bridges,
permissions и состав сборок не меняются. Firefox использует тот же модуль;
deploy.py копирует каталог, deploy-firefox.py уже включает файл модуля,
deploy_VZID.py не включает поиск ИД. Изменения сборщиков не требуются.

Проверка: регрессия на 21469 совпадениях, границы страниц и полный результат,
синтаксис модуля и существующие тесты поиска.
