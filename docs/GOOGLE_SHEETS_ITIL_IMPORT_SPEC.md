# Импорт таблицы ITIL в Google Sheets

## Спецификация

Цель: добавить в меню Google Sheets по `F2` отдельный блок `Заявки ITIL`, чтобы пользователь мог вставить большую таблицу из буфера обмена и записать её на лист `ITIL`.

Пользовательский сценарий:
1. Пользователь открывает таблицу Google Sheets и нажимает `F2`.
2. В блоке `Заявки ITIL` нажимает `Загрузить таблицу`.
3. Открывается модалка с большим полем для вставки.
4. Пользователь вставляет через `Ctrl+V` таблицу целиком, вместе с первой строкой заголовков.
5. Расширение проверяет формат вставки и показывает сводку по числу строк.
6. После подтверждения расширение отправляет данные в Apps Script bridge небольшими порциями.
7. Bridge записывает значения на лист `ITIL`, начиная с ячейки `A2003`.

Ограничения и правила:
- ожидается TSV-таблица из буфера обмена;
- ожидается 22 столбца;
- первая строка вставки должна содержать заголовки таблицы;
- запись идёт только значениями;
- старые строки ниже диапазона вставки не очищаются;
- вставка идёт прямо поверх диапазона, начиная с `A2003`.

Ожидаемые заголовки:
- `Индекс картинки события`
- `Статус порядок`
- `Дата`
- `Приоритет`
- `Номер`
- `Текущий этап`
- `Наименование`
- `Номер заявки в СУПП`
- `Дата передачи заявки в СУПП`
- `Состояние в СУПП`
- `Дата состояния заявки СУПП`
- `Инициатор`
- `Текущий исполнитель`
- `Комментарий исполнителя`
- `Крайний срок устранения`
- `Дата завершения`
- `Массовый`
- `Время перехода`
- `Маршрут`
- `Организация`
- `Исполнитель в ПК СУПП`
- `Последний исполнитель`

## План

1. Добавить в `F2` новый блок `Заявки ITIL` над блоком `Заявки WSS`.
2. Добавить модалку с textarea для вставки TSV-таблицы.
3. На клиенте валидировать 22-колоночный формат и ожидаемые заголовки.
4. Реализовать отправку таблицы в bridge небольшими порциями.
5. На стороне bridge добавить действие, которое пишет значения на лист `ITIL`, начиная с `A2003`, без очистки старых данных.
6. Скрывать новую модалку при screenshot-mode так же, как остальные элементы Google Sheets UI.

## Задачи проверки

1. Проверить синтаксис `GoogleSheets/problem_picker_content.js`.
2. Проверить синтаксис `GoogleSheets/GoogleAppsScript/ProblemPickerBridge.gs`.
3. Выполнить точечную UTF-8/mojibake-проверку изменённых файлов с русским текстом.
4. Проверить staged diff и состав коммита.

## Прямое чтение буфера (октябрь 2026)

Сценарий: скопировать полную таблицу с заголовками в 1С, открыть «Загрузить таблицу» и нажать «Загрузить из буфера». Расширение читает текст без помещения всей выгрузки в textarea, проверяет заголовки и строки до первой записи, затем автоматически загружает данные. Обычная вставка остаётся запасным способом.

План и задачи:
1. Читать буфер по нажатию кнопки: readText, затем доступные текстовые/HTML-форматы через read, затем резервный execCommand('paste') в невидимое поле существующего окна. Пустой ответ браузера не считать доказательством пустого системного буфера; показывать диагностику способов и форматов без содержимого заявок.
2. Разбирать строки с периодической передачей управления браузеру; не отображать полную выгрузку из буфера.
3. Отправлять не более 300 строк и примерно 512 КиБ JSON за запрос. Слишком большую отдельную строку отклонять до записи.
4. Показывать количество подтверждённых строк. При сбое сохранять данные и позицию в памяти вкладки; кнопка «Продолжить загрузку» повторяет неподтверждённую порцию по тому же адресу, без добавления дубликатов.
5. Сохранить диапазон A2003:V и существующее правило: хвост предыдущей выгрузки не очищается. До завершения не запускать поиск новых заявок.
6. Проверить большую таблицу, неверные заголовки, ограничение размера порции и продолжение после ошибки. Проверить включение файла в Chrome/Edge и Firefox-сборки и скрытие существующего окна при скриншоте.

Новых постоянных данных и ключей хранения нет: буфер и прогресс живут только в памяти вкладки. Перезагрузка страницы сбрасывает продолжение; повторная загрузка начинается с A2003 и перезаписывает те же ячейки.

Быстрый запуск: перезагрузить расширение и страницу Google Sheets, скопировать таблицу из 1С, нажать F2 → «Заявки ITIL» → «Загрузить таблицу» → «Загрузить из буфера». Дождаться сообщения о завершении, затем выполнить обычный поиск новых заявок и сбор текстов. Работу с реальным буфером 1С необходимо подтвердить в Edge.

Результаты проверки: тест на синтетической таблице из 12 000 строк подтвердил разбор, ограничения порций, проверку заголовков и продолжение с того же диапазона после ошибки. С имитацией браузерных API проверены пустой/запрещённый readText, резервный read с текстом и HTML, execCommand('paste') и удаление временного поля. Реальный Edge/1С не проверен из-за ошибки подключения браузерного расширения Codex.

Состав сборок: deploy.py копирует изменённый файл; deploy-firefox.py уже включает его и сохраняет clipboardRead. deploy_VZID.py собирает только StageTimer, поэтому этот импорт в его состав не входит. Новые корневые элементы UI не добавлены: кнопка и временное поле находятся внутри существующего окна, уже скрываемого в screenshot-mode.

Основание выбора API: [MDN — работа с буфером в расширениях](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Interact_with_the_clipboard). Дополнительных разрешений не требуется.

## Помощник Windows для буфера 1С

Проверка на реальной выгрузке: обычный GetClipboardData не получил текст; после OleInitialize и создания служебного окна запрос CF_UNICODETEXT получил 6 349 906 байт за 1,073 секунды. Повторное обычное чтение заняло 0,002 секунды. Пользователь подтвердил, что после этого Ctrl+V в Google Sheets работает без Блокнота.

Согласованный сценарий: фоновый `1c_clipboard_warmer.pyw` запускается при входе в Windows, отслеживает изменение буфера и запрашивает текст только при наличии форматов `1C:Moxcel8 Document` или `1C:Moxcel Document`. После подготовки пользователь вставляет таблицу обычным Ctrl+V. Пока идёт подготовка большой выгрузки, возможна короткая задержка.

Окно «1С:ITIL Управление информационными технологиями предприятия. КОРП, редакция 1.2 (TMN-VPTERM.VOSTOK-ELECTRA.RU)» принадлежит mstsc.exe: это удалённое приложение. Фильтр по имени 1cv8.exe не используется. Определение таблицы по её форматам буфера работает и с перенаправлением буфера через RDP.

План/задачи: сохранить исходник в GoogleSheets; установить копию в папку Startup пользователя; запустить pythonw без окна; проверить синтаксис, запуск и защиту от второго экземпляра. Существующие скрипты Startup не менять. Помощник использует только стандартную библиотеку Python, OLE и служебное окно Windows. Буфер не перезаписывается, содержимое не сохраняется; служебный лог содержит только время, размер и ошибки. Новых пользовательских данных и ключей Supabase нет.

Автозагрузка: `%APPDATA%/Microsoft/Windows/Start Menu/Programs/Startup/1c_clipboard_warmer.pyw`. Исходник не подключается в manifest или Firefox/StageTimer-сборку; это отдельный помощник Windows. deploy.py копирует каталог GoogleSheets без изменения поведения расширения. Сборочные скрипты дорабатывать не требуется.

Диагностика: `%TEMP%/1c_clipboard_warmer.log` (ограниченный размер). Остановка: создать `%TEMP%/stop_1c_clipboard_warmer.txt`; для отключения будущего запуска удалить только этот .pyw из Startup. При следующем запуске старый сигнал остановки очищается.

Проверка установки: копия в Startup совпадает с исходником, синтаксис проверен без создания __pycache__, процесс pythonw запущен, второй экземпляр корректно завершается по mutex. Свежую выгрузку после установки пользователь проверяет обычным Ctrl+V.
