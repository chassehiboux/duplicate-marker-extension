# Спецификация: повторные запросы ЕПГУ по неуспешным взыскателям

## Пользовательский результат

В окне «Сводка ЕПГУ» появляется кнопка «Отправить запросы по неуспешным».
Она помогает последовательно создать по одному новому запросу для каждого взыскателя,
у которого за текущий день ещё нет результата «Услуга оказана».

Перед отправкой пользователь видит отдельное окно со списком таких взыскателей.
Любого взыскателя можно снять галочкой. Снятые галочки сохраняются и восстанавливаются
при следующем открытии окна, в том числе после входа в расширение на другом браузере.

## Переключение баз

В верхней части окна «Сводка ЕПГУ» расположен компактный переключатель из трёх баз:

- «Курган» — департамент `39`;
- «Основная» — департамент `66`, «Тюмень и Тюменский участок (АСРН)»;
- «ЮРИЦ» — департамент `70`, `ООО "ЮРИЦ"`.

Переход выполняется по актуальной ссылке соответствующего пункта штатного dropdown,
поэтому служебный токен авторизации не хранится в расширении. После загрузки страницы
выбранной базы окно «Сводка ЕПГУ» открывается автоматически и показывает данные нового
грида. Активная база определяется только по hostname и выделяется на любом департаменте:

- `kgn.pyramid.vostok-electra.ru` — «Курган»;
- `pyramid.vostok-electra.ru` — «Основная»;
- `yuric.pyramid.vostok-electra.ru` — «ЮРИЦ».

Название открытого департамента рядом с переключателем не показывается.

Для автоматического открытия используется одноразовый локальный маркер с коротким
сроком жизни. Он удаляется после успешного открытия или при истечении срока и не
синхронизируется с Supabase, поскольку не является пользовательской настройкой.

## Правила отбора

1. Учитываются строки текущего грида с датой запроса за сегодняшний день.
2. Название взыскателя берётся из текста до последних скобок, ФИО — из последних скобок.
3. Для каждого взыскателя определяется лучший статус за день.
4. Взыскатель попадает в повторную отправку, если лучший статус отличается от
   «Услуга оказана».
5. Все ФИО, уже встречавшиеся сегодня у этого взыскателя, считаются использованными
   независимо от статуса запроса.
6. В системном списке выбирается первая строка этого взыскателя с ФИО, которого ещё
   нет среди сегодняшних запросов.

## Сценарий отправки

Для каждого отмеченного взыскателя расширение строго последовательно:

1. нажимает системную кнопку «Создать запрос»;
2. подтверждает системный вопрос;
3. ждёт появления формы `/ovzid/epgurequests/form`;
4. выбирает подходящую пару «взыскатель + ФИО»;
5. нажимает «Отправить запрос»;
6. ждёт сообщения «Запрос успешно создан»;
7. закрывает системное окно и переходит к следующему взыскателю.

Одновременная отправка нескольких запросов запрещена. Если система вернула ошибку
или ответ не пришёл за отведённое время, пакет останавливается, а пользователь видит,
на каком взыскателе и с какой причиной это произошло.

Если у взыскателя не осталось неиспользованных ФИО, пакет приостанавливается и
показывает вопрос «ФИО закончились. Хотите начать заново?» с кнопками «Да» и «Нет».
При ответе «Да» учёт использованных ФИО сбрасывается только для текущего взыскателя,
после чего выбирается первое ФИО в штатном списке. При ответе «Нет» новые запросы не
создаются, состояние остаётся прежним, а пользователь возвращается в «Сводку ЕПГУ».

После подтверждённого сброса новый цикл продолжается между повторными запусками кнопки:
в гриде находится первое повторившееся ФИО после полностью пройденного списка, а
использованными считаются только ФИО начиная с этого места. Поэтому следующие запуски
выбирают второе, третье и остальные ФИО нового цикла. Вопрос о новом сбросе появляется
только после использования всего актуального списка формы ещё раз.

После успешной обработки всех выбранных взыскателей расширение полностью перезагружает
текущую страницу, как при нажатии F5. Перед перезагрузкой сохраняется одноразовый признак,
поэтому после загрузки актуального грида окно «Сводка ЕПГУ» открывается снова автоматически.

## Окно выбора и прогресс

- По умолчанию отмечены все взыскатели, кроме сохранённых исключений.
- Для каждой строки показаны лучший статус, количество сегодняшних запросов и уже
  использованные ФИО.
- Доступны команды «Выбрать всех» и «Снять все».
- Кнопка запуска показывает фактическое количество выбранных взыскателей.
- После запуска список превращается в журнал выполнения со статусами: ожидание,
  отправка, успешно, пропущено или ошибка.
- Закрытие окна во время выполнения не отменяет уже отправленный запрос; кнопка
  закрытия блокируется до завершения текущего шага.

## Хранение данных

Новый ключ `dup_epgu_retry_excluded_claimants_v1` содержит нормализованный список
взыскателей, для которых пользователь снял галочку. Ключ добавляется в существующую
KV-синхронизацию `public.extension_user_state`; миграция БД не нужна.

Текущий прогресс пакета не хранится постоянно: после перезагрузки страницы запуск
нужно начать заново. Это предотвращает неявное продолжение отправки после сбоя.

## Безопасность и совместимость

- Финальная отправка начинается только после явного нажатия пользователем в окне
  выбора.
- Следующий запрос не создаётся до подтверждённого успеха предыдущего.
- Основная кнопка, оба окна и прогресс скрываются в режиме создания скриншота.
- Функция входит в существующий пункт F2 «Сводка ЕПГУ».
- Используется уже имеющееся разрешение `scripting`; новых permissions и ресурсов нет.
- Основная и Firefox-сборка получают одинаковое поведение.
- Обособленный StageTimer получает только общий CSS без активной логики ЕПГУ.
