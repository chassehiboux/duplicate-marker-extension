# Спецификация перекрёстной проверки паспорта, ИНН и даты смерти

## Цель

Функция проверяет сведения выбранных EDoc текущей базы Пирамиды по внутренней истории записей и независимым внешним источникам. Она ничего не изменяет в Пирамиде: результат только показывается, копируется и выгружается в Excel.

## Запуск

- Пункт меню StageJump называется «Проверить паспорт / ИНН / смерть» и расположен рядом с «Скопировать инфо об ИД».
- Если в текущем загруженном гриде выделены строки, проверяются только они.
- Если выделенных строк нет, проверяется строка, из меню которой вызвана команда.
- Жёсткого ограничения количества строк нет.
- Повторяющиеся люди, паспортные наборы и ИНН проверяются один раз, но итог формируется отдельно для каждого исходного EDoc.

## Границы поиска

- Проверка выполняется только в текущей открытой базе Пирамиды.
- Текущий EDoc всегда остаётся исходным кандидатом, даже если связанная история не найдена.
- Другие базы Пирамиды не опрашиваются.

## Сбор данных Пирамиды

Для каждого исходного EDoc загружается полная карточка: EDocID, DebtID, лицевой счёт, ФИО, дата рождения, адрес, паспорт, дата выдачи, ИНН и дата смерти.

История паспортов собирается по алгоритму:

1. Поиск долгов по ФИО.
2. Выбор строк с точным ФИО и лицевым счётом исходного EDoc.
3. Сбор уникальных полных адресов найденных долгов.
4. Поиск долгов по точному ФИО и каждому адресу.
5. Загрузка всех связанных EDoc по уникальным DebtID.
6. Выбор EDoc с точным совпадением ФИО и даты рождения.
7. Сбор паспортов РФ с четырьмя цифрами серии и шестью цифрами номера, дат выдачи, ИНН и источников.
8. Загрузка всех страниц результатов без ограничения первой страницей.

Отдельно фиксируются внутренние противоречия: несколько ИНН, разные даты выдачи одного паспорта, одинаковая дата у разных паспортов, отсутствие текущего паспорта в истории и другие неоднозначности.

## Внешние проверки

### Поиск ИНН ФНС

- Используется прямой запрос `POST https://service.nalog.ru/inn-new-proc.json` после программного подтверждения согласия.
- Первый поиск выполняется с датой выдачи паспорта.
- Если ИНН не найден, запрос повторяется без даты выдачи.
- Если ИНН найден только без даты, паспорт считается подтверждённым, а дата выдачи — сомнительной.
- Новые поиски запускаются последовательно с интервалом не менее 11 секунд.
- Отрицательный ответ, техническая ошибка и капча являются разными состояниями.

### Капча

- При каждом требовании капчи пользователь получает явное уведомление.
- Очередь поиска ИНН принудительно ждёт 30 секунд.
- После ожидания создаётся новая сессия, и тот же запрос повторяется с обычным интервалом 11 секунд.
- Количество повторов не ограничено. Проверка продолжается до успешного ответа либо ручной отмены пользователем.

### Дата смерти ФНС

- Для каждого уникального ИНН Пирамиды и каждого найденного ФНС ИНН вызывается `POST https://service.nalog.ru/invalid-inn-proc.json`.
- Возвращённая дата смерти в рамках функции считается датой смерти.
- Ответ относится к номеру ИНН и сам по себе не доказывает принадлежность этого ИНН выбранному человеку.

### Нотариат

- Используется прямой `POST https://notariat.ru/api/probate-cases`.
- Запрос выполняется по ФИО и дате рождения без передачи даты смерти Пирамиды.
- Обрабатываются все найденные записи.
- Отсутствие наследственного дела не считается доказательством отсутствия смерти.

## Правила выводов

Паспорт, ИНН и дата смерти оцениваются независимо. Отсутствие внешнего результата не превращается в утверждение о неверности данных.

### Паспорт

- «Подтверждён» — ФНС вернул ИНН по текущему паспорту с датой выдачи.
- «Подтверждён, дата выдачи сомнительна» — результат найден только без даты выдачи.
- «Подтверждён другой паспорт» — текущий паспорт не подтверждён, а связанный вариант подтверждён.
- «Не подтверждён внешним источником» — ФНС не вернул ИНН ни по одному варианту.
- «Противоречивые паспортные данные» — есть взаимоисключающие подтверждённые или внутренние сведения.
- Если подтверждены несколько исторических паспортов, вероятно текущим считается паспорт с самой свежей датой выдачи, но все варианты остаются видимыми.
- Если не подтверждён ни один вариант, функция не выбирает «правильный» паспорт.

### ИНН

- «Подтверждён паспортом» — ФНС вернул ИНН Пирамиды.
- «ФНС вернул другой ИНН» — паспорт подтверждён, но ИНН отличается.
- «В Пирамиде отсутствует, найден ФНС».
- «Несколько ИНН в связанных EDoc».
- «Только внутренняя согласованность Пирамиды» — номер повторяется в истории, но внешняя принадлежность не установлена.
- «Не подтверждён» или «Не проверен».

### Дата смерти

- Совпадение Пирамиды с двумя внешними источниками.
- Совпадение с одним внешним источником.
- Внешняя дата при отсутствии даты в Пирамиде.
- Несовпадение с внешней датой.
- Расхождение ФНС и Нотариата — обязательная ручная проверка без приоритета одного источника.
- Отсутствие внешней даты — «Внешнего подтверждения нет», а не «Человек жив».

### Общий итог

- «Данные согласованы».
- «Данные согласованы с оговорками».
- «Требует внимания».
- «Есть явное расхождение».
- «Проверка выполнена не полностью».

Каждый итог сопровождается текстовой причиной и исходными доказательствами.

## Интерфейс и результат

Новое окно показывает общий прогресс, текущий этап и отдельное состояние каждого EDoc. Статусы паспорта, ИНН, даты смерти и общего вывода обновляются сразу после получения соответствующего ответа, а не только после завершения всей пачки.

В каждой строке прямо в окне видны основание вывода и конкретные источники. При наведении на статус показывается расширенная подсказка, а блок «Все проверенные данные и ответы источников» раскрывает паспортные варианты, ответы ФНС, результаты проверки недействительности ИНН, найденные наследственные дела, внутренние противоречия и технические ошибки.

Окно должно полностью помещаться в видимую область браузера: шапка и нижняя панель не выходят за правую границу, длинные сообщения переносятся, список результатов прокручивается независимо. Доступны отмена, повтор технических ошибок, копирование результатов и ручное скачивание Excel.

Excel не скачивается автоматически. Пользователь самостоятельно запускает выгрузку отдельной кнопкой после появления хотя бы одного результата. Имя файла:

`Проверка_паспортов_ИНН_смерти_Курган_2026-08-10_14-35.xlsx`

Листы:

- «Итоги» — одна строка на исходный EDoc;
- «Паспортные варианты» — все варианты и источники;
- «Ошибки и проверки» — состояния внешних запросов и ошибки.

Результаты существуют только в памяти текущей страницы и в скачанном файле. Постоянное локальное хранение и Supabase-синхронизация не требуются.
