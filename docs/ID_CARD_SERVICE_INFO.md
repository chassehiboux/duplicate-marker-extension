# ТМ и глобальный поиск в карточке ИД

## Спецификация

- В «Служебной информации» карточки `/ovzid/fullcard/<EdocID>` с новой строки показывается «ТМ:» с названием StatusID. Идентификаторы и ссылка «В ДЕБТ» сохраняются.
- Основной справочник берётся из предоставленного пользователем `StatusID - StatusName.xlsx`. В расширение включаются только StatusID и StatusName.
- Если кода нет в Excel и в сохранённых названиях, открывается неактивная вкладка глобального поиска в той же базе и Firefox-контейнере. Вкладка фильтруется по DebtID из служебного блока, раскрывается строка этого БП. Среди должников выбирается точный EdocID; название берётся из колонки «Статус дела».
- Перед сохранением повторно проверяется, что исходная карточка содержит те же EdocID, DebtID, StatusID. При изменении статуса во время поиска старый код не получает новое название.
- Сохраняются только соответствия код → название, отдельно по hostname базы. Вкладка закрывается при успехе, ошибке и тайм-ауте. При следующем открытии известного кода новая вкладка не нужна. Параллельные запросы одного кода в одной базе объединяются; разные коды обрабатываются последовательно.
- При отсутствии результата или доступа показывается «Неизвестный статус (StatusID: …)» с причиной в подсказке. Ошибки и пустые названия не сохраняются. Повторное открытие разрешает новую попытку.
- Первой кнопкой «Действия по EdocID» становится «Переход в глобальный поиск». Она использует существующий StageJump и DebtID из служебного блока текущей карточки, включая iframe. Если EdocID не совпадает или карточка ещё загружается, переход блокируется с понятным сообщением.
- Поле ТМ управляется существующей настройкой `idCardCheckTools` в F2 и скрывается при скриншоте. Кнопка наследует настройки и скрытие существующего меню.
- Данные карточки на сервере Пирамиды не изменяются. Долговечный ключ `dup_status_names_cache_v1` добавляется в Supabase-синхронизацию: клиентский и серверный allowlist, отдельная миграция, применение через MCP и проверка БД. Кэш не содержит ФИО и долгов.
- Поле и fallback работают в основном расширении и обособленном StageTimer. Кнопка действий относится к основному расширению: в StageTimer нет меню «Действия по EdocID».

## План / задачи

1. Импортировать и проверить все строки Excel; сохранить справочник и происхождение данных.
2. Добавить общий модуль служебного блока и фоновый поиск отсутствующих названий.
3. Добавить первую кнопку к существующему меню и StageJump.
4. Обновить F2, скрытие при скриншотах и все затронутые сборки.
5. Добавить и применить миграцию Supabase для кэша названий.
6. Проверить известный код, отсутствующий код, повторное открытие, ошибку/тайм-аут, точный EdocID при нескольких должниках, смену исходного StatusID, iframe и сборки.
7. Закоммитить только изменения задачи; существовавшие правки пользователя оставить вне коммита.

## Scope gate

- StageTimer: да, общий модуль и фоновый fallback; интеграция таймера с Google Sheets не меняется.
- Firefox: да, content/background scripts, сохранение контейнера фоновой вкладки.
- Manifest/ресурсы/deploy: да; отдельному StageTimer нужен `scripting` для чтения грида.
- UI/F2/скриншоты: да.
- Постоянные ключи / Supabase: да, `dup_status_names_cache_v1`.
- Apps Script / Google Sheets bridge: нет.

## Источники

Основной источник — Excel пользователя, получен 13.10.2026: 407 уникальных строк с числовым StatusID. Строки описаний исключены. Файл является данными; его содержимое не используется как инструкции.

Первичный поиск pyramid-knowledge нашёл частичные списки ТМ ВЗИД, РДЗ и СРФЛ; после предоставления Excel они не используются как основной справочник. Пример `100322` / «Склад (иски)» дополнительно подтверждён живой карточкой и колонкой «Статус дела» глобального поиска. Новые коды разрешаются через текущий интерфейс Пирамиды по сценарию пользователя.

## Quickstart

Перезагрузить расширение и открыть карточку `28055705`: «ТМ: Склад (иски)». Первая кнопка действий открывает глобальный поиск по DebtID `7499025`. В карточке с новым кодом дождаться фонового поиска; найденное название появляется на месте ожидания и используется при следующем открытии. Если поиск завершился ошибкой, причина доступна в подсказке поля.

## Проверено 13.10.2026

- Сохранённый Chrome, настоящая карточка: поле ТМ и первая кнопка меню. Вкладка поиска после нажатия содержит только DebtID `7499025`.
- Fallback проверен удалением `100322` из справочника в тестовом контексте: найдено «Склад (иски)», кэш заполнен, неактивная вкладка закрыта. Повторный запрос использует кэш без открытия вкладки.
- Скрытие ТМ по настройке F2 и в режиме скриншота; несовпадающий EdocID отклоняется.
- Автотесты: объединение параллельных запросов, сохранение Firefox-контейнера, закрытие при ошибке/тайм-ауте, отсутствие ложного кэша, повторная попытка после ошибки, смена StatusID исходной карточки.
- Миграция `allow_status_names_cache_sync` применена через MCP. Сервер разрешает новый ключ; прежние разрешения и исключение временного списка карточек сохранены.
- Сохранение выполняется через `__dupSupabaseSync.syncSet`, а не простую запись storage: в живой сессии подтверждена одна операция в outbox для найденного названия. Фактический REST push отложен: существующая сессия сообщает об исчерпанной квоте Supabase и паузе отправки. После восстановления квоты сработает штатная очередь.
- Фоновая вкладка использует `active: false`. Для Firefox `cookieStoreId` требует `cookies`, добавленного в обособленную сборку; основание — [MDN tabs.create](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/create).
- StageTimer Chrome/Firefox и исходники основной Firefox-сборки собираются с новым модулем. Подпись и публикация Firefox в этой задаче не выполнялись.
- Кэш названий в основном расширении синхронизируется существующей Supabase-сессией. В StageTimer подключён тот же клиент синхронизации; облачный перенос требует входа в Supabase в этой отдельной установке. Статистика таймера остаётся исключённой из Supabase.
