# StageTimer Error Incidents Spec

## Цель

Сделать так, чтобы в рабочее время StageTimer фиксировал два типа инцидентов:

- ошибки grid/stage при загрузке или фильтрации;
- ошибки ЕПГУ по самой свежей строке запросов в карточке ИД.

Инциденты должны:

- записываться в Google Sheets;
- попадать в одну редактируемую Telegram-сводку;
- не смешиваться с обычной телеметрией времени загрузки.

## Рабочие интервалы

Часовой пояс: `Asia/Yekaterinburg`.

Поддерживаются только интервалы:

- `08:00-12:30`
- `12:30-17:00`

Вне этих интервалов:

- инциденты не отправляются;
- в Google Sheets ничего не пишется;
- Telegram-сводка не обновляется.

## Типы инцидентов

### GRID

Инцидент фиксируется, когда на странице появляется видимый `.ui-jqgrid-errorbar` с реальным текстом ошибки.

Не считаются инцидентом:

- ошибки после ручного `abort`;
- errorbar с текстом `Загрузка/Фильтрация была прервана пользователем вручную. Повторите действие заново.`;
- errorbar в коротком окне подавления сразу после подтверждённого ручного `abort`.

### EPGU

Инцидент фиксируется на вкладке `/ovzid/fullcard/{edocid}/epgu`, если у самой свежей строки таблицы запросов поле `Статус отправки` начинается с `Ошибка:`.

Исторические ошибки без ошибки в самой свежей строке инцидентом не считаются.

## Дедупликация

Внутри одного рабочего интервала одинаковые инциденты схлопываются в одну запись.

Сигнатуры:

- GRID: `base + department + user + url + error_text`
- EPGU: `base + department + user + edocid + sent_at + status_text`

При повторе одинаковой сигнатуры:

- новая строка не создаётся;
- увеличивается счётчик повторов;
- обновляется `last_seen`.
- каждое новое срабатывание дополнительно пишется в служебный лог инцидентов для точных счётчиков и динамики `30м`.

## Telegram-сводка

Используется одно постоянное сообщение.

- сообщение создаётся один раз;
- дальше обновляется только через `editMessageText`;
- новые StageTimer-сообщения идут после него.

Сводка обновляется раз в минуту и показывает:

- текущий рабочий интервал;
- счётчик `GRID` за интервал;
- динамику `GRID` за последние 30 минут;
- последний пример `GRID` отдельно по каждой базе;
- счётчик `EPGU` за интервал;
- динамику `EPGU` за последние 30 минут;
- последний пример `EPGU` отдельно по каждой базе.

## Google Sheets

Для инцидентов используются отдельные листы по базам:

- `Ошибки_Основная`
- `Ошибки_<База>`

Дополнительно используется скрытый служебный лист `Инциденты_Лог` для точного подсчёта количества инцидентов и динамики за последние 30 минут.

Колонки:

- `first_seen`
- `last_seen`
- `interval_key`
- `type`
- `base`
- `department`
- `user`
- `edocid`
- `debtid`
- `page_url`
- `context`
- `epgu_sent_at`
- `epgu_request_type`
- `summary_text`
- `full_text`
- `signature`
- `repeat_count`
