# Спецификация: поиск должников в реестрах ФССП

## Пользовательский результат

На странице «Реестры из ФССП» в нижней панели после кнопки «Единый реестр ФССП»
появляется кнопка «Найти ИД в реестрах».

По кнопке открывается окно пакетного поиска. В каждой строке можно указать один или
несколько признаков должника:

- номер ИП — поиск по `RegNumIP`;
- ФИО — поиск по `FullName`;
- дата рождения — поиск по `BirthDay`;
- номер ИД — поиск по `EDNumber`;
- статус записи внутри реестра — поиск по `StatusName`.

Значения сопоставляются без учёта регистра и могут быть полными или частичными. Пустое
поле не участвует в поиске. Точное служебное значение `null` означает поиск пустого
значения; об этом сообщает полупрозрачная подсказка «null для поиска пустых» внутри поля.
Все заполненные поля одной строки должны совпасть у одной записи должника.
Статус можно указать самостоятельно или вместе с другими признаками. Он проверяется
у записи внутри реестра, а не у самого реестра в общем списке.

## Ввод нескольких должников

Изначально показана одна пустая строка. Как только пользователь вводит значение в любое
поле последней строки, ниже автоматически появляется новая пустая строка. Фокус и позиция
курсора не меняются. Полностью пустая последняя строка в поиск не попадает.

Список из одного столбца Excel можно вставить через Ctrl+V в любое поле. Каждая
непустая строка становится отдельным значением выбранного столбца, начиная с текущей
строки формы. Значения этого столбца заменяются, остальные поля сохраняются.
Недостающие строки добавляются автоматически; в конце остаётся пустая строка.
Пустые строки пропускаются, пробелы по краям удаляются. Обычная вставка одного значения
сохраняет стандартное поведение. Вставка нескольких столбцов одновременно отклоняется
с подсказкой скопировать один столбец. После запуска поиска вставка недоступна.

## Область поиска

Поиск использует текущий отфильтрованный список реестров: активные фильтры и сортировка
jqGrid считываются в момент запуска. Каждая страница списка обрабатывается сразу после
загрузки: расширение проверяет все подходящие реестры этой страницы и только затем
запрашивает следующую. Предварительная загрузка всех страниц списка не выполняется.

Страницы отдельных реестров во время поиска не открываются. Расширение выполняет прямые
авторизованные GET-запросы:

- `/ovzid/fsspreestr/data` — все страницы текущего списка реестров;
- `/ovzid/fsspreestr/{ID}/typedata` — все страницы записей конкретного реестра.

Реестры со статусом «Проведен (нет данных)» можно пропускать, поскольку в них нет строк
должников. Остальные реестры одной страницы проверяются с ограниченным параллелизмом,
чтобы не создавать резкую нагрузку на Пирамиду. Следующая страница списка загружается
только после завершения текущей.

Во время поиска доступна кнопка «Стоп». Она переводит поиск в паузу: уже начатые запросы
могут корректно завершиться, но новые реестры и страницы не начинают загружаться. Кнопка
меняется на «Продолжить» и возобновляет тот же поиск с сохранённым прогрессом и уже
найденными совпадениями. Закрытие окна, как и раньше, полностью отменяет поиск.

Закрытие окна отменяет активные сетевые запросы через `AbortController` и прекращает поиск.

## Прогресс и результаты

После нажатия «Поиск» окно показывает текущую страницу списка, количество проверенных
реестров и найденных совпадений. Результаты обновляются по мере поиска.

Таблица ввода содержит только критерии должника. Под ней расположены кнопки управления,
прогресс и раскрываемые блоки результатов: по одному на каждую заполненную строку
поиска. Блоки создаются сразу после нажатия «Поиск», до первых сетевых запросов,
в том же порядке, что и строки ввода. Пустые строки не создают блоков; одинаковые
условия в разных строках сохраняют отдельные блоки.

Заголовок блока содержит номер, введённые условия и счётчик «Найдено: 0», который
обновляется при обнаружении совпадений. По умолчанию блок свёрнут. При раскрытии
показывается таблица со столбцами «№», «Номер ИП», «ФИО», «Д.р. должника»,
«Номер ИД», «Статус» и «ID реестра». Раскрытые блоки остаются открытыми при обновлении
результатов. Блоки без совпадений остаются видимыми, включая завершение поиска.
Заголовки блоков с нулём совпадений подсвечены жёлтым; при появлении хотя бы одного
совпадения подсветка автоматически меняется на зелёную вместе со счётчиком.
Внутри каждого блока строки отсортированы по числовому ID реестра по убыванию.
Ссылка открытия показывает ID и тип реестра прямо в тексте; если тип отсутствует,
вместо него выводится «Тип не указан».
Правая кнопка мыши на любой ячейке найденной записи копирует её отображаемое значение
в буфер обмена. Для ячейки открытия копируется ID вместе с типом реестра.
Копирование передаёт только обычный текст (`text/plain`), без HTML и оформления,
включая резервный способ копирования. При вставке используется формат ячейки Excel.
После копирования окно показывает подтверждение; строки с сообщением об отсутствии
совпадений не копируются. Копирование не зависит от общего режима копирования таблиц.

Каждое совпадение добавляется в таблицу результатов отдельной строкой сразу после
обнаружения. В строке отображаются фактические значения найденной записи. Если один
должник найден несколько раз внутри одного реестра или в разных реестрах, каждая
подходящая запись занимает отдельную строку. Счётчики показывают число записей, а не
число уникальных реестров. ID является
ссылкой вида `https://<текущая-база>/ovzid/fsspreestr/{ID}` и открывается в новой вкладке.

При наведении на ссылку с ID появляется подсказка с типом реестра из `TypeName`
общего списка. Если тип отсутствует, подсказка сообщает «Тип реестра: не указан».
Дополнительные запросы для получения типа не требуются.

Если совпадений пока нет, внутри блока показывается нейтральная подсказка. Ошибка отдельного
реестра не останавливает остальные проверки; после завершения показывается количество
реестров, которые не удалось прочитать.

## Переход к найденному должнику

Ссылка дополнительно передаёт расширению ID найденной строки. После открытия страницы:

1. jqGrid выбирает минимальный доступный размер страницы, достаточный для показа всех
   записей реестра (например, 100 для 86 записей), либо максимальный доступный размер;
2. при необходимости открывается страница грида, на которой находится найденная строка;
3. выполняется автоматическая прокрутка к строке;
4. строка три раза мигает зелёным.

## Интерфейс, скриншоты и настройки

Окно выполнено в утилитарном стиле существующей Пирамиды, занимает почти всю доступную
высоту экрана и остаётся доступным с клавиатуры. Список блоков результатов занимает основное
свободное место и прокручивается независимо от формы поиска. Новый интерфейс:

- скрывается в режиме создания скриншота;
- имеет отдельный пункт в меню F2;
- работает одинаково в основной Chrome/Chromium- и Firefox-сборке.

## Хранение данных

Введённые данные и результаты не сохраняются в `chrome.storage.local` и не передаются в
Supabase. Они существуют только в открытом окне до его закрытия, поэтому синхронизация
постоянных данных поиска не требуется. Единственный постоянный ключ видимости пункта F2
`dup_ui_show_fssp_registry_search` синхронизируется существующим Supabase-механизмом для
префикса `dup_ui_show_`.
