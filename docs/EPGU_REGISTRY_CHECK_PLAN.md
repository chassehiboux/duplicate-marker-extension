# План: проверка формирования реестров ЕПГУ

1. Добавить локальную модель результата проверки, нормализацию взыскателей и правила
   агрегирования статусов.
2. Передавать в background список всех департаментов активной базы и ссылку возврата в
   исходный департамент.
3. В background открыть неактивную вкладку, последовательно переключать департаменты и
   читать `/ovzid/fsspreestr/data` за текущий день со всех страниц.
4. Гарантированно восстановить исходный департамент, закрыть служебную вкладку и вернуть
   фокус исходной вкладке.
5. Сохранять только полностью успешный дневной результат в локальном кэше без Supabase.
6. Добавить кнопку запуска, прогресс, второй статус, количество реестров и раскрывающуюся
   таблицу в существующую сводку ЕПГУ.
7. После успешной проверки без перезагрузки перерисовывать открытую сводку сохранёнными
   данными.
8. Проверить синтаксис, агрегацию статусов, удаление устаревшего кэша, Chrome/Firefox и
   актуальность deploy-скриптов.
9. Ограничить обход постоянно отображаемыми департаментами и сохранять статусы реестра
   отдельно по каждому найденному департаменту.
10. Добавить в раскрывающуюся таблицу цветные статусы, фиксированные размеры, подсказку
    департаментов, копирование имени файла по ПКМ и компактную кнопку проведения.
11. Реализовать проведение в отдельной вкладке через штатный интерфейс Пирамиды, повторное
    чтение статуса, обязательный возврат исходного департамента и точечное обновление кэша.
12. Проверить реальный пользовательский цикл в сохранённом профиле Chrome и выполнить
    точечные проверки изменённых файлов.
13. Сделать повторную проверку инкрементальной: обходить только департаменты без данных или
    с неположительными статусами и объединять результат с сохранённой положительной частью.
